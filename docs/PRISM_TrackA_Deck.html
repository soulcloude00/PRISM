What it is

A Lakehouse that unifies 6 campus datasets into a Skills Knowledge Graph with constraint-aware GraphRAG — only feasible skill→course→lab→JD paths are retrieved.

  • Supervisor routes across 3 focused Genie Agents (sharded for accuracy)
  • Cited answers + AI/BI dashboard overlay (student / officer / admin views)
  • Feasible only: respects prerequisites, lab hours, GPU, eligibility

3 Pillars

1. Graph — SubgraphRAG lightweight MLP retriever, NodeRAG heterograph (SOTA without fine-tuning)
2. Constraints — Graph retrieval enforces physical/temporal constraints (2026 campus twin paper)
3. Conversational — Genie IS the product, not a chatbot add-on

Complete journey: “At-risk for Infosys?” → graph reasoning → 2 skills + 2 labs free tonight + alumni path — all cited.

Architecture — Built 100% on Free Edition

Lakehouse → Graph → Genie → Action

Open Data + Synthetic Campus Data (120k rows)
  ↓ Lakeflow Designer (visual pipelines) → Delta Lake Bronze/Silver/Gold → Unity Catalog (governance + lineage)
  ↓ Lakebase (Postgres) ← live student queries / lab bookings (transactional agent memory)
  ↓ Vector Search (Hybrid) + Knowledge Graph → SubgraphRAG / NodeRAG (GraphRAG)
  ↓ Agent Bricks: Supervisor → [ Information Extraction (JDs→skills) | Retrieval (cited) | Forecasting (risk) ]
  ↓ Genie Agents x3 (sharded: Skills | Labs | Academic) → Genie Conversation APIs + MCP → AI/BI Dashboard overlay
  ↓ MLflow 3.0 (LLM judges: groundedness/accuracy) + Model Serving + Databricks Apps

Genie Code auto-generates & debugs pipelines/notebooks. ZeroOps ready.

Lakebase = operational DB for agents — no silo, direct on lakehouse.

Agent Bricks = declarative agents, auto-evals via TAO/ALHF.
